# 새단장 설계와 검증 기록

- 작성: 2026-11-12
- 작업 방식: 작성과 검수를 분리했다. 한 사람이 구현하고 다른 사람이 독립적으로 재계산·재실행해 검수했다.
- 근거 등급: A 원문 확정 / B 실측 / C 문서·선례 / D 추정

## 2. 고정 정의

- **간선 방향**: `source → target`은 항상 "source의 변화가 target에 영향"을 뜻한다. 소프트웨어 의존 관계에서 "X가 Y를 쓴다"는 `Y → X`로 넣는다. 이 뒤집기는 변환기만 담당한다.
- **선형 엔진**: `x[t+1] = (1 − λ)·x[t] + A·x[t] + u[t]`, `A[target, source] = weight`, `0 < λ ≤ 1`, 자기 간선 금지.
  - 불안정 판정은 **스펙트럼 반경** `ρ((1 − λ)I + A) < 1`으로 한다. Gershgorin(노드별 유입 |w| 합 < λ)은 legacy 정규화에만 쓴다. 유입 합이 λ를 넘어도 안정한 그래프(예: w = 0.8, λ = 0.5인 사슬, ρ = 0.5)는 받아들인다.
  - 스펙트럼 반경은 강연결 성분(SCC)별로 계산한다. M은 성분 순서로 블록 삼각이라 ρ(M)은 성분별 최댓값이고, 단일 노드 성분은 정확히 1 − λ다. 성분이 2,000개 이하이면 밀집 eigvals로, 그보다 크면 고정 시작 벡터의 ARPACK으로 계산하고 수렴하지 않으면 실패로 처리한다. 큰 비정규(비순환에 가까운) 행렬에 전역 고유값 계산을 쓰면 틀린 값이 나오기 때문이다(검수 지적).
  - **증폭 상한**: 스펙트럼 반경은 수렴만 보장하고 크기는 보장하지 않는다. 명세의 `max_amplification`(기본 1,000배)을 넘는 실행은 `AmplificationExceededError`로 거부하고, 특이·오버플로 풀이는 `NumericalBlowupError`로 실패시킨다.
  - 출력 이름: 일회성 충격은 `cumulative_impulse_impact`, 지속 충격은 `persistent_steady_state`. 두 값 모두 `(λI − A)⁻¹ s`이지만 묻는 질문이 다르다.
  - 자르기는 하지 않는다. 고립 노드도 `s/λ`로 1을 넘을 수 있고, 화면에는 "직접 충격 1 대비 배수"로 보여 준다.
  - 노드가 500개를 넘으면 희소 행렬과 희소 풀이(`spsolve`)를 쓴다.
- **DebtRank** (Battiston 외 2012): 영향 가중치는 0~1이고 음수 간선(완충)은 실행 시 거부한다. 비활성 노드도 손실값은 계속 누적하지만 다시 전파하지 않는다(원 논문과 동일). 노드 가치는 `NodeSpec.value`를 비율로 정규화해 쓴다.
- **불확실성**: 모든 가중치와 λ는 범위 `[low, high]`로 넣는다. 분포는 균등이고 시드는 명세에 둔다. 불안정 표본은 버리지 않고 `unstable_fraction`으로, 폭발 표본은 `explosive_fraction`으로 결과에 함께 낸다. 이 비율 자체가 취약도 지표다.
- **순위**: |영향|이 충격 합의 1e-12배 이하인(도달하지 않은) 노드는 순위에 넣지 않는다.
- **민감도**: 자유 매개변수가 60개 이하면 Sobol(S1, ST), 넘으면 Morris 선별을 쓴다. 표본에 불안정 모형이 섞이면 결과를 내지 않고 명시적으로 실패한다.

## 3. 모델 명세

- 프리셋 `.py` 8개를 `scenarios/*.yaml` 선언형으로 바꿨다. pydantic으로 검증하고(`extra="forbid"`) `yaml.safe_load`만 쓴다. 파일 이름은 화이트리스트 패턴으로 받고, 저장소 안의 파일만 읽는다.
- 기존 프리셋 중 2개만 이식했다(`scripts/export_legacy_specs.py`). 방향을 복원할 수 없어 양방향·미검증·`normalization: legacy_in_strength`로 두었다. 상단 범위에서도 유입 합이 0.9·λ_low 이하가 되도록 재조정해 모든 표본이 안정하다. 재조정한 가중치는 상관이 아니라 "영향의 몫"이다.

## 4. 검증 관문

### P0 엔진 (도메인 중립)
1. 같은 포화 검사가 기존 엔진을 실제로 잡아낸다(검사기도 검사한다)
2. 새 엔진은 같은 입력에서 포화하지 않고, 충격 크기에 선형으로 반응한다
3. 음의 충격에서 부호가 정확히 대칭이다
4. 비순환 그래프에서 하류 충격이 상류로 가지 않는다
5. 간선 방향 시험(`a → b`면 b 충격이 a에 가지 않음)
6. 불안정 그래프는 거부하고, 유입 합이 커도 안정한 그래프는 받아들인다
7. 닫힌 해와 반복 계산이 일치한다(누적합, 정상상태)
8. DebtRank가 손계산 예제와 일치한다
9. 같은 시드에서 같은 결과가 나온다
10. 희소 경로와 밀집 경로가 일치한다
11. 큰 비순환 그래프(사슬 600·2,000, 층상 900)의 ρ가 정확히 1 − λ이고 실행마다 같다. 큰 그래프 안의 순환은 여전히 거부한다
12. 수렴하지만 폭발하는 모형과 특이 풀이는 명시적 오류로 실패한다
13. 도달하지 않은 노드에 순위 확률을 주지 않는다
14. 검수자의 독립 정답표 대조

### 의존 관계 영향 조회 (전파 엔진 탑재 여부 판정)
- 질문: 소프트웨어 의존 관계 그래프에서, 전파 엔진이 단순 사용처 추적(전이 폐쇄)보다 변경의 영향 대상을 잘 고르는가.
- 방법: 테스트 시스템의 소프트웨어 의존 관계 자료로 평가했다. 기준선은 전이 폐쇄(홉 순서)와 "같은 패키지 전부"이고, 모형은 유입 차수로 정규화한 선형 엔진이다. 정답은 변경 이력에서 만든 대리 라벨(짧은 기간 안의 후속 변경)이다. 판정 상수(사례 30건 미만이면 판정 불가, 상위 10개 재현율에서 0.05 이상 앞서야 함)는 결과를 보기 전에 고정했다.
- 결론: 단순 추적을 넘지 못해 **전파 엔진을 얹지 않았다**. 사례 수가 적어 공식 판정은 "판정 불가"다. 대리 라벨은 의존 관계에 의한 영향보다 "함께 개발되는 묶음"을 주로 담고 있어, 이 라벨로는 어떤 전파 모형도 제대로 시험할 수 없었다.
- 코드: `cxsim/sap.py`(추출 파일 검증과 영향 방향 그래프 변환), `cxsim/evaluation.py`, `scripts/p1_sap_pipeline.py`. 자료는 저장소에 넣지 않는다.

### 산업 충격 (주 도메인)
한국은행 산업연관표를 쓴다. 공개 자료라 누구나 같은 결과를 재현할 수 있다.

#### 관문 1 — 엔진이 공표 생산유발계수와 같은가
- 수요 모드: λ = 1, `A[target = i, source = j] = a_ij`(투입계수, 전치 없음)
- 결과: 2020 실측표(생산자가격·기초가격)와 2019 연장표(생산자가격) 세 파일 모두에서 엔진의 역행렬이 공표 "생산유발계수" 시트와 전 원소 일치했다(최대 절대오차 8.9e-16). 일치한 짝은 **국산 투입계수 Ad**이고, 총 투입계수 A로는 0.59~0.76만큼 어긋난다. 따라서 공표 시트는 (I − Ad)⁻¹ = [I − (I − M̂)A]⁻¹ 유형이다.
- 국산 투입계수에는 아주 작은 음수 칸이 있다(1차 금속 행 등). 한국은행 보고서가 설명하는 잔폐물·부산물의 부(負)의 투입 처리이며, 정상 값으로 보고만 했다.
- 검사기 검사: 전치와 1e-7 오프셋을 일부러 넣은 변이는 실데이터에서 실패했다.

#### 관문 2 — 2020 코로나 수요 충격 되맞히기

**이 시험이 무엇인가.** 2020 산업연관표의 최종수요는 같은 해 생산 통계와 한 회계 체계 안에서 추계된 값이다. 따라서 이 시험은 예측이 아니라, "실현된 수요가 주어졌을 때 2019 구조의 간접 파급이 독립된 생산 통계와 맞는가"를 보는 구조 일관성 점검이다. 모형과 직접 효과 기준선이 둘 다 이 누출의 덕을 보므로, 의미 있는 숫자는 각각의 수준이 아니라 둘의 차이다. 충격 크기 예측, 공급 측 제약, 가격 효과는 재지 않는다.

**열람 범위.** 두 표의 국산거래표 최종수요 열, 2019 표의 산출액(충격 이전 수준), 분류표·대조표, 물가지수는 사양을 정하기 전에 볼 수 있었다. 2020 표의 산출액·중간수요는 쓰지 않았고(회계 항등식이 되므로), 결과 변수인 생산지수 실적은 예측을 고정한 뒤에만 열었다. 2020 표의 산출액 열은 코드 수준에서 읽기를 막았다.

**충격 벡터.**
- 국산 최종수요 = 민간소비 + 정부소비 + 민간·정부 고정자본형성 + 수출(9111, 9112, 9121, 9122, 9140). 재고증감과 귀중품은 산출의 잔차 성격이 강해 결과 정보가 새어 들어오므로 뺐다.
- 기준년 단절 처리(사양 수정 1·2): 2019 연장표(2015년 기준)와 2020 실측표 사이에는 기준년 개편에 따른 수준 단절이 있었다. 표만 비교하면 2020년 민간소비가 명목 +8.6%로 나오지만, 같은 기준의 국민계정은 −3.8%였다. 그래서 2020 표의 항목 안 부문 구성비는 유지하고, 항목 합계를 국민계정의 2019→2020 명목 성장률에 맞춰 재조정했다(안 A). 그다음 부문별 생산자물가지수로 실질화했다.
  - 국민계정 항목 성장률(명목/실질, %): 민간소비 −3.8/−4.6, 정부소비 +6.7/+5.2, 민간 고정자본 +3.9/+2.6, 정부 고정자본 +4.2/+3.6, 수출 −5.7/−1.7
  - 민감도로 2020 표를 쓰지 않는 구성 고정안(안 B: 2019 구성 × 국민계정 실질 성장률)도 함께 봤다. 개편 효과가 섞인 원래 식은 실행하지 않았다.
- 물가 대응은 `data/ppi_to_io33_gate2.csv`(대응 지수가 없는 6부문은 가장 가까운 상위 지수 사용), 업종 대응은 `data/ksic_to_io33_gate2.csv`(한국은행 IO-KSIC 대조표의 품목 수 다수결)에 있다. 두 표 모두 결과를 보기 전에 커밋했다.

**모형과 기준선.**
- 모형: Δx̂ = (I − Ad₂₀₁₉)⁻¹ Δf (관문 1 엔진). 성장률은 Δx̂ / x₂₀₁₉
- 기준선 D(직접 효과만, 핵심 비교): Δf / x₂₀₁₉
- 기준선 U(전 부문 동일 비율): ΣΔf / ΣFD₂₀₁₉. 상수라 평균절대오차만 비교한다.

**결과 변수.** 통계청 광공업생산지수(2020=100, 원지수, 연평균)의 2020/2019 성장률, 주 비교 15부문(광산품, 공산품 13, 전력·가스). 여러 업종이 한 부문으로 묶일 때는 2019년 업종별 부가가치로 가중했다(공식 지수 가중치를 구할 수 없어 쓴 근사, 사양 수정 3). 보조로 서비스업생산지수(불변) 12부문을 봤다.

**판정 규칙 (사전 고정).**
- "파급이 설명력을 더한다" = 순위상관 차이(모형 − 직접) ≥ 0.10 이면서 모형의 평균절대오차가 직접 효과 이하이고 동일 비율보다 작음
- 그 밖은 "더한다고 볼 수 없다"
- 부트스트랩 90% 구간이 0을 포함하면 문턱을 넘었더라도 "방향만 확인, 우연과 구별되지 않음"으로 표기
- 안 A와 안 B, 또는 명목 민감도에서 판정이 엇갈리면 "불안정"으로 표기
- 사전 고정 민감도: 명목, 재고·귀중품 포함, 14부문(전력·가스 제외), 구성 고정(안 B). 가중치 민감도: 2019 생산액 가중, 단순 평균

- 구성 고정(안 B)에서는 모형과 직접 효과 모두 순위상관이 0에 가깝다. 부문 순위의 설명력은 2020 표의 부문 구성에서 나온 것이며, 이 시험은 그 구성을 뺀 상태의 파급에 대해서는 아무것도 말하지 못한다.
- 서비스 보조 결과는 해석하지 않는다. 기준년 재분류로 보이는 큰 충격(도소매·금융·교육)이 섞여 있다.
- 소표본: 부문 15개, 사건 1개의 기술 통계다. n = 15에서 순위상관의 표준오차는 약 0.27이라 유의성은 주장하지 않는다.
- 검수자가 독립 코드로 원자료부터 다시 계산해 일치를 확인했다(예측 최대 상대오차 2.2e-14, 지표 최대 차이 2.7e-15).

**재현과 사전 고정의 증거.**
- 관문 2 예측 파일(`gate2_predictions.json`)의 SHA-256은 `512f059813268b976566392d492071b98a95629062229d1d6d44997f1df087bd`이다. 이 저장소의 `scripts/p1_industry_gate2_predict.py`와 공개 통계(한국은행 ECOS 산업연관표·국민계정·생산자물가지수)로 누구나 같은 파일을 다시 만들어 해시를 대조할 수 있다. 결과 파일을 열지 않고 만들어지는 파일이다.

#### 산업 검증 종료와 제품 위치
- 관문 2 판정을 확정하고 산업 검증을 닫았다. 결과를 본 뒤 떠오른 분석(특정 부문 제외, 분기 자료)은 실행하지 않았다.
- 2021 차량용 반도체 사건은 이 설계로 하지 않았다. 공급 측 충격이라 수요 모형이 다루지 못하고, 15부문으로는 0.07 크기의 차이를 가릴 힘이 없기 때문이다.
- 재검토 조건(둘 다 충족해야 함): "간접 파급이 정확도를 높인다"는 주장이 필요할 때, 그리고 같은 기준년의 표 쌍과 83부문 이상(n ≥ 60)으로 사전 등록할 수 있을 때.
- 산업 모듈의 위치는 **"산업연관 시나리오 계산기"**다. 예측기라고 부르지 않는다. 화면과 문서의 고정 문구:
  > 공표 생산유발계수와 일치하는 계산입니다(관문 1). 2020년 되맞히기에서 간접 파급은 부문 순위 설명을 문턱 이상 높이지 못했고, 오차 크기는 직접 효과만 볼 때보다 0.3~0.7%p 작았습니다(15부문, 사건 1개, 유의성 주장 없음).

#### 산업연관 시나리오 계산기
- 입력: 2020 실측표 국산 Ad(33부문)와 부문별 최종수요 변화(조원 또는 2020 국산 최종수요 대비 %, 점 또는 최소~최대 범위)
- 출력: 직접·간접·합계 생산 변화, 2020 산출 대비 %, 생산유발 배수(모든 충격의 부호가 같을 때만), 상위 10부문 그림, 33부문 표
- 범위는 계산이 선형이므로 구간 연산으로 정확한 최소·최대를 낸다.
- 단위 충격의 결과가 공표 생산유발계수 열과 일치한다(실데이터, 오차 1e-12 이내). 파일을 불러올 때마다 엔진 역행렬을 공표값과 다시 대조한다.
- 2020 국산 최종수요가 0 이하인 부문(광산품, 기타)은 % 입력을 받지 않는다.
- 통합 문서의 7MB 서식 정보를 건너뛰는 값 전용 읽기와 해시 키 캐시로 첫 로딩이 27초에서 0.13초로 줄었다. 읽은 값은 기존 라이브러리와 전 시트에서 같다.

### 제외
증시 네트워크(최신 인과탐색이 단순 기준선에 자주 진다는 벤치마크 결과), LLM 에이전트 군집 예측(검증 표준 부재), 그래프 편집 화면, 공급 모드(Ghosh), 가격 모형.

## 5. 스택

Python 3.12 이상, NetworkX, numpy/scipy, pydantic 2, PyYAML, SALib, openpyxl, Streamlit. 라이선스상 AGPL·GPL 라이브러리는 쓰지 않는다. 가상환경은 클라우드 동기화 폴더 밖에 두기를 권한다.

## 6. 운영 원칙

- 작성과 검수를 분리한다. 검수자는 결과를 보고서만으로 받지 않고 직접 재실행·재계산한다.
- 판정 기준과 예측은 결과 자료를 열기 전에 커밋한다. 결과를 본 뒤 생긴 분석은 실행하지 않고 별도로 올린다.
- 새 작업은 세 질문을 통과해야 들어온다: 현재 관문을 통과시키는 데 필요한가, 없으면 판정이 달라지는가, 지금 안 하면 나중에 못 하는가.
- 데이터 파일은 저장소에 넣지 않는다. 입력 파일은 SHA-256을 출처 기록과 대조한 뒤에만 읽는다.
- 기존 엔진은 화면 기본값에서 뺐다. "레거시 화면(결함 재현용)" 토글과 회귀 시험에서만 쓴다.
